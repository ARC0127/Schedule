# Schedule 0.0.4

## 简体中文

### 修复重启后项目与记录变空

已确认根因：从 MSIX 版 Codex 启动的子进程会继承 AppData 文件重定向。同一个 `%LOCALAPPDATA%\CodexJournal` 路径，在 Codex 和桌面资源管理器下可能指向不同的实际文件。之前的重载修复没有解决这个启动环境差异。

- 统一数据目录为 **`%USERPROFILE%\.schedule`**。桌面快捷方式、Codex 启动和单实例激活使用同一个位置。
- 第一次升级自动查找旧 AppData 日志和包缓存中的旧日志。先将来源文件及其 `.bak` 备份至新目录的 `legacy-backups`，再迁入有内容的记录。旧文件保留不动。
- 迁移保留整个 JSON，包括项目、日期、想法 ID、完成状态、多项目绑定、图片和日程。图片内嵌在数据中，不需要重新添加。
- 若多份旧日志都有不同内容，启动会提示冲突并指出备份目录，避免静默覆盖。请先核对各副本，将确认的 `journal.json` 放入新目录，再启动。
- 新目录已有日志时，不会再次导入旧数据或恢复已删除的记录。沿用原子保存、过期写入拒绝和加载失败禁止编辑。

### 下载与升级

下载 **`Schedule-0.0.4-windows-x64.zip`**。先从托盘退出旧版，再将压缩包完整解压到原程序目录。继续使用原来的 `Journal.exe` 和快捷方式。

今后的备份位置是 `%USERPROFILE%\.schedule`。升级后请使用新版，旧版仍会读写旧目录。不要删除迁移备份，确认项目、记录和图片齐全后再自行归档。

## English

### Fix empty projects and entries after restart

The confirmed cause was inherited MSIX AppData redirection. A Schedule process launched by the MSIX edition of Codex could see a different physical file at the same `%LOCALAPPDATA%\CodexJournal` path than a process launched from Explorer. The previous document-reload fix did not resolve this launch-context difference.

- Data now lives in **`%USERPROFILE%\.schedule`**, shared by desktop and Codex launches and single-instance activation.
- First startup finds legacy AppData journals and redirected package-cache journals. It backs up source files and their `.bak` files under `legacy-backups`, then imports the populated journal. Original files are left untouched.
- Migration copies the complete JSON, retaining projects, dates, idea IDs, completion, multiple project bindings, inline images, and events.
- Different populated histories cause a visible conflict with a backup location instead of a silent overwrite. Review the copies and place the confirmed `journal.json` in the new directory before restarting.
- Once the new journal exists, old data is never imported again. Atomic saves, stale-write rejection, and failed-load editing protection remain in place.

### Download and upgrade

Download **`Schedule-0.0.4-windows-x64.zip`**. Exit the old version from the tray, then extract the complete archive over the original program folder. Keep the existing `Journal.exe` name and shortcut.

Back up `%USERPROFILE%\.schedule` from now on. Use the new version after migration; older versions still write to the old directory. Retain migration backups until you have checked your projects, entries, and images.
