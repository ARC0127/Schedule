# Schedule · Windows 0.0.13 + Android 1.1.12

## 中文

本次发布包含 Windows 0.0.13、Android 1.1.12，以及两端合并下载包。

- 后台自动同步：两端首次选择配对设备并启用后，默认每 2 小时尝试同步，恢复连接后同步一次。已保存改动会在空闲后触发尝试，未保存草稿与待确认冲突会延后同步。Windows 可留在托盘，Android 使用后台同步通知。
- 自动模式使用现有网络，不启动手机临时热点、不切换电脑 Wi-Fi。手动同步仍保留热点加速。原图增量分批传输、项目绑定与电脑端冲突确认继续保留。
- 应用内 OTA 更新：Windows 顶栏的下载图标，Android「同步」页底部的「软件更新」。点击检查正式版本，查看版本说明，再下载并安装。
- 更新来源固定为 ARC0127/Schedule 的 GitHub Release。按平台分别比较版本，不降级，不使用预发布包。下载后校验 GitHub 提供的 SHA-256。
- Windows 在安装前保存编辑内容、创建数据快照，退出后替换程序文件并重启。复制失败时尝试恢复旧程序，保留备份和错误详情。用户数据目录不参与程序替换。
- Android 额外校验包名、版本号和现有应用签名。安装交给系统确认，首次需允许 Schedule 安装应用。覆盖安装保留记录、原图和设置，不要先卸载。
- 包含 Android 1.1.11 的断线监听重建与详细错误信息。已报告的实机 Windows 蓝牙错误 10022 仍未确认解决，OTA 不依赖手机与电脑之间的同步连接。

第一次仍需手动覆盖安装本版本，之后才能从应用内更新。Windows 退出旧版后覆盖原程序目录，保留 `%USERPROFILE%\.schedule`。Android 直接打开同签名 APK 覆盖安装，不要卸载或清空数据。两端分别联网获取更新，不通过蓝牙传递安装包。已安装当前最新版本时显示没有更新，网络不可达时明确报告失败，可稍后重试。

验证范围：Windows 更新版本选择、下载完整性、真实发布包下载、退出后安装与复制失败恢复已测试。Android 模拟器已验证包名／版本／签名校验、只读安装文件提供及覆盖升级后的记录、日程、原图保留。没有把模拟器结果视为红米 K70 实机安装或蓝牙问题已解决的证明。

## English

This release includes Windows 0.0.13, Android 1.1.12 and a combined download containing both apps.

- Background automatic sync: select the paired device and enable sync once on both sides. Attempts run every two hours by default, after reconnection and after saved changes become idle. Unsaved drafts and pending conflicts defer synchronization. Windows can stay in the tray; Android uses a background sync notification.
- Automatic mode uses existing connections without starting a phone hotspot or switching Windows Wi-Fi. Manual sync retains hotspot acceleration. Incremental original-image transfer, project bindings and desktop conflict review remain available.
- In-app OTA: use the download icon in the Windows toolbar or Software updates at the bottom of Android's Sync page. Check stable releases, read the notes, then download and install.
- Updates come only from ARC0127/Schedule GitHub Releases. Platform-specific versions are compared independently; older and prerelease builds are excluded. Downloads must match GitHub's SHA-256 digest.
- Windows saves edits and creates a data snapshot before exiting, replacing program files and restarting. Copy failures trigger restoration of prior program files, with backups and error details retained. Application data is not replaced.
- Android additionally verifies package identity, increasing version and the installed application's signing identity. Android asks for installation confirmation and, on first use, permission to install apps. Install over the current app without uninstalling it.
- Includes Android 1.1.11 listener recovery and detailed errors. The reported physical Windows Bluetooth error 10022 remains unresolved; OTA does not rely on the phone-to-PC sync connection.

Install this bootstrap version manually once. Quit the older Windows app before replacing its program files and keep `%USERPROFILE%\.schedule`. Install the same-signed Android APK over the existing app without uninstalling or clearing data. Future updates can be installed in the app. Each device downloads over its own internet connection. If the latest version is already installed, no update is offered. Network failures remain visible and can be retried later.

Validation covers Windows version selection, download integrity, a real published download, installation after parent exit and restoration after copy failures. Android emulator checks cover package/version/signature validation, the read-only installer provider and retention of records, events and original images after an in-place upgrade. These results do not establish Redmi K70 installation behavior or resolution of the physical Bluetooth issue.
