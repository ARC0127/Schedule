# Schedule · Windows 0.0.12 + Android 1.1.10

### Android 1.1.11 local follow-up / 安卓本地修复包

手机遇到传输断线后，退出旧 RFCOMM 监听，由后台服务在 30 秒后重建，保留设备选择和自动同步开关。错误详情保留外层超时原因；Wi-Fi 协商中断时也保留已捕获的加密握手失败信息。普通草稿或校验失败不会重建监听。电脑程序版本仍为 0.0.12。

After a transport disconnect, Android closes the old RFCOMM acceptor and schedules a replacement after 30 seconds, retaining the selected device and automatic-sync setting. Details preserve timeout context and captured TLS authentication errors. Draft and validation failures do not restart the listener. Windows remains at 0.0.12.

实机仍出现 Windows 蓝牙错误 10022，重新开关手机自动同步后也未消失。因此本包修复恢复路径，并未确认消除这次物理连接故障。覆盖安装后仍需在红米 K70 上验证。

The physical connection still returns Windows Bluetooth error 10022 after toggling phone auto-sync. This package repairs recovery behavior; resolution of that physical failure remains unverified on the Redmi K70.

## 中文

- 电脑同步提示区分当前连接状态与上次成功时间，移除要求一直打开手机页面的旧文案。系统错误放入可展开详情，明确区分自动同步和手动热点加速。

- 自动检查与手动同步共用连接占用保护，避免同时向手机开启两条会话。新版两端在检查到改动后复用当前蓝牙连接，减少断开后立即重连。
- 手机选定电脑后立即保存选择并按开关状态启动后台同步，移除重复的“等待电脑连接”操作。继续默认每 2 小时同步，重连和保存后的改动也会触发同步。
- 增加 Android 伴侣设备后台连接授权。首次在同步页点击“允许后台自动连接”，通过系统确认后，可由系统在已关联电脑重新连接时唤醒服务。授权仅针对所选电脑，暂停同步后不会自动恢复。
- 连接中断时保留监听并等待电脑重试。失效监听器自动重建，旧会话回调不会关闭新连接。通知显示等待自动重连，同步页可展开查看原始错误及阶段。
- 保留电脑冲突确认、未保存草稿保护、原图分块与已完成图片复用。自动同步只用现有局域网或蓝牙，手动同步仍可使用临时热点。

Windows 保持托盘运行，可在托盘菜单开启“开机启动”。Android 允许附近设备、通知和一次性后台连接授权。HyperOS 的后台自启动与省电限制仍由系统管理，强行停止应用后需重新打开。伴侣设备唤醒支持 Android 12 及以上且系统提供该能力的设备；旧系统继续使用前台服务。蓝牙经典设备的系统唤醒依据连接事件，不代表应用能从任意距离唤醒手机。

已知范围：通知中的单独 `broken pipe` 不足以定位用户这次断连的具体原因。本次修复已确认的会话重叠和监听恢复问题，并增加后续诊断信息。测试使用隔离 Windows 客户端、Android 模拟器和本机传输，不能代替红米 K70 的物理无线与长时间后台测试。

覆盖安装同签名 APK，**不要卸载或清空数据**。电脑覆盖程序文件并保留 `.schedule`。本地开发包，GitHub 发布链接仍指向已发布版本。

## English

- Desktop sync messages separate current connection status from the last successful sync. Obsolete instructions to keep the phone page open are removed. Expandable details retain system errors, and automatic sync is distinguished from manual hotspot acceleration.

- Automatic checks and manual transfers share an exclusive connection guard. Updated peers reuse the probe connection when a transfer is due instead of immediately disconnecting and reconnecting.
- Selecting a computer now persists it and starts listening when automatic sync is enabled. The separate “Wait for Windows” step is removed. The default remains two hours, with reconnect and saved-change triggers.
- Android adds one-time companion-device approval for background reconnection. Choose “Allow background reconnection” and approve the selected computer in the system dialog. Presence callbacks respect both the selected device and the pause switch.
- Interrupted transports keep listening for retries. Failed listeners restart, and callbacks from old sessions cannot close a replacement connection. Notifications show reconnection status; the sync page retains technical error details and phases.
- Desktop conflict review, draft protection, original-image chunks and completed-file reuse remain in place. Automatic sync uses LAN or Bluetooth without switching networks; manual sync retains hotspot acceleration.

Keep Windows running in the tray; its menu offers startup at sign-in. Grant Android Nearby devices, notifications and the one-time background connection approval. HyperOS still controls background startup and battery restrictions. Force-stopping requires reopening the app. Companion wake-up requires Android 12 or later and system support; older devices retain the foreground listener. Classic Bluetooth presence is based on connection events, not arbitrary-distance wake-up.

A notification containing only `broken pipe` does not establish the cause of the reported disconnect. This update repairs confirmed overlapping-session and listener-recovery issues and improves diagnostics. Isolated Windows, emulator and local-transport tests do not establish physical Redmi K70 radio or long-running background reliability.

Install the same-signed APK over the current app; **do not uninstall or clear data**. Replace Windows program files while retaining `.schedule`. These are local development packages; GitHub download links still target the published version.
