# Schedule · Windows 0.0.11 + Android 1.1.9

## 中文

- 默认每 2 小时自动尝试双向同步，可在电脑同步设置中改为 1、4 或 8 小时。选择并启用可信的已配对设备后，电脑在运行期间检查连接，重连后同步一次，保存后的改动也会在空闲后同步。
- Android 使用独立的设备连接前台服务。离开同步页或关闭主页面后仍可等待电脑，通知栏提供暂停入口。首次需要选择电脑并允许附近设备权限。
- 自动同步优先现有局域网，不自动启动手机热点或切换电脑 Wi-Fi。手动同步保留临时热点加速。
- 保留电脑端冲突确认。有冲突时暂停自动提交，等待逐项选择，不用修改时间决定覆盖。
- 未保存的手机草稿会延后同步。两端使用共享的保存保护、原图分块与中断重试机制。

电脑需运行 Schedule（托盘即可）且处于唤醒状态，手机需允许后台服务。系统省电、强行停止应用、关闭蓝牙或设备不在附近会推迟同步。重新打开应用或恢复连接后继续尝试。HyperOS 的具体后台保活与实际无线连接需在真机核对。

升级：电脑退出托盘后覆盖程序目录，保留 `.schedule` 数据。手机直接覆盖安装同签名 APK，不要卸载或清空数据。

## English

- Automatic two-way sync defaults to every two hours. Choose one, four or eight hours in Windows sync settings. After selecting and enabling a trusted paired device, Windows checks availability while running, syncs once on reconnect, and syncs saved changes after an idle period.
- Android uses a separate connected-device foreground service. Leaving the sync page or closing the Activity keeps the listener available. Its notification offers Pause. Select the paired computer and grant Nearby devices permission once.
- Automatic sync prefers the existing LAN and never starts a temporary phone hotspot or switches Windows Wi-Fi. Manual sync retains hotspot acceleration.
- Conflicts still pause record changes for explicit desktop review. Modification timestamps never decide which version wins.
- Unsaved Android drafts defer synchronization. Existing guarded saves, original-image chunks and retry behavior are retained.

Windows must be awake with Schedule running, including in the tray. Android must allow the background service. Battery restrictions, force-stop, disabled Bluetooth or distance can postpone work. Reopening the app or restoring connectivity allows retries. Physical HyperOS background lifetime and radio behavior still require device testing.

Upgrade Windows program files while keeping `.schedule`. Install the same-signed APK over the existing Android app; do not uninstall or clear data.
