# Schedule v0.0.3

## 中文

修复界面重新加载后使用旧启动快照、导致已保存项目和想法显示为空或回退的问题。

- 每次加载界面都通过原生接口读取当前日志文件，加载完成后才允许编辑和保存。
- 如果磁盘文件已发生变化，拒绝用旧的内存状态覆盖它，并提示保留未保存修改后按 F5 重新读取。
- 读取失败会显示错误并禁用编辑，不再把加载失败当成一个空白日志。
- 内容未变化时不重复写入，也不轮换上一版 `.bak` 备份。
- Windows 关闭请求统一先同步编辑区，再收进托盘，避免绕过尚未完成的保存。
- 保持原有数据位置、想法 ID、项目绑定、完成状态、图片和附件格式。

下载 `Schedule-0.0.3-windows-x64.zip`，解压后运行 `Journal.exe`。更新前请从托盘选择“退出”，再替换程序文件。个人数据仍在 `%LOCALAPPDATA%\CodexJournal\journal.json`，不要删除该目录。`.bak` 是上一版备份，不是第二个数据库。

验证覆盖保存后刷新、Windows 关闭按钮进入托盘、再次启动恢复窗口、完全退出重开、图片及绑定保留、拒绝过期写入、读取失败后恢复。仍为单用户 JSON 存储，不提供外部工具并发写入或自动合并接口。

## English

Fixes document reloads restoring an outdated startup snapshot, which could make saved projects and ideas appear empty or revert to older content.

- Each document load reads the current journal through the native bridge. Editing and saving stay disabled until loading finishes.
- Saves reject a file that changed since it was loaded. The error asks you to copy unsaved edits before pressing F5 to reload.
- Read failures display an error and block editing instead of treating the journal as empty.
- Unchanged saves no longer rewrite the file or rotate its previous `.bak` backup.
- Windows close requests flush pending editor changes before hiding the app in the tray.
- Existing data locations, idea IDs, project bindings, completion states, images, and attachment formats are preserved.

Download `Schedule-0.0.3-windows-x64.zip`, extract it, and run `Journal.exe`. Before replacing app files, choose **Exit** from the tray menu. Personal data remains in `%LOCALAPPDATA%\CodexJournal\journal.json`; keep that directory. The `.bak` file is the previous backup, not a second database.

Verified saved-state reloads, the Windows close-to-tray path, reopening the tray window, full process restarts, image and binding preservation, stale-write rejection, and recovery after a failed read. Storage remains single-user JSON, without concurrent external editing or automatic merging.
